## Browser gateway prerequisite (not yet a renderer)
`browser-gateway.mjs` uses the existing DNS-pinned HTTPS collector in binary, single-hop mode. It permits GET only, excludes WebSocket/EventSource request types and never forwards caller headers, cookies or bodies. It preserves only selected response headers (including CSP), rejects compressed responses and returns redirects for re-interception at their actual URL. Per session: 40 requests, 4 concurrent, 256000 bytes/resource, 5000000 bytes cumulative with concurrent reservations, and a 20-second absolute deadline. A fresh gateway is required per render; close it on cleanup. Defaults are conservative and may prevent some pages from rendering completely: record those limits explicitly.

## Opt-in macOS browser renderer
`browser-render.mjs` exports `renderPublicPage(url, {chromium, executablePath})`. Supply an explicitly installed Playwright Chromium API (including routeWebSocket) and an absolute browser executable path. No runtime is resolved from an owner's app installation by production code. The browser launches through `/usr/bin/sandbox-exec` with `(deny network*)`; intercepted requests are fulfilled by the separate bounded DNS-pinned HTTPS gateway. There is no unsandboxed fallback. A fresh temporary profile is used; service workers, downloads and WebSocket routes are blocked. Render settling is at most 500ms, DOM at most 256000 bytes, session at most 20s. Sandbox protection here is network confinement, not a complete hostile-code filesystem/CPU sandbox.

`collectEvidence(..., {renderPage})` can append separately identified rendered observations; raw observations remain intact and failed/cross-origin rendering is explicitly unavailable. Default watcher does not enable this callback yet. Bounded raw-response/DOM comparison is implemented for title, descriptions, H1, canonical, robots metadata and JSON-LD blocks. It pairs only the exact final navigation response; subsequent document reloads invalidate pairing. Differences are observations, not JavaScript causality or crawler visibility proof. No screenshots are implemented. Before enabling for customer targets, make the runtime dependency portable and test browser redirect/deadline/cleanup controls and bounded screenshots. Runtime fixtures require `AUDIT_BROWSER_TEST_RUNTIME` (absolute Playwright module path) and `AUDIT_BROWSER_TEST_CHROME`; ordinary tests explicitly skip real-browser cases without these variables.

Validated this pass: actual JavaScript DOM changes, rejected private HTTP/POST/beacon requests, blocked WebSocket route, independent macOS EPERM on a direct loopback socket; owned-domain title rendered through 3 requests / 194247 bytes, zero denied routes. These controls do not prove every Chromium exploit or channel safe. 42 tests passed with real-browser fixtures enabled. No paid service needed.
